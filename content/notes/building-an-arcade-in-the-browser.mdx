The hard part of a 3D portfolio is not the 3D. It is making sure the 3D never
gets in the way of the words. Three decisions carried most of that weight.

## One canvas, never unmounted

The scene lives in the root layout, outside the routed children. Navigating
does not tear down a WebGL context and rebuild it; it changes a target vector
that the camera chases. Route changes become camera moves.

<Callout type="tip" title="The cheap version of this">
If you only take one thing from this: put the canvas above the router, not
inside it. Everything else follows from that.
</Callout>

## Content is DOM, not texture

It is tempting to render text onto the cabinet screens with a render target.
It looks incredible in a demo and is miserable to actually read. Selectable
text, real scrolling, and working screen readers all come free if the content
is a DOM layer and the 3D stays behind it.

The compromise is that the cabinet screens run an attract-mode shader instead
of the real content. Five cabinets, five draw calls, zero render targets:

```glsl
if (uVariant < 0.5) {
  p = patternRings(vUv, t);
} else if (uVariant < 1.5) {
  p = patternBlocks(vUv, t);
}
```

Branching on a uniform is coherent across the whole draw, so the cost is the
branch taken, not the sum of all of them.

## Tiers, not a toggle

Device capability is guessed once from core count, memory, pointer type, and
the GPU renderer string, then demoted at runtime if frames drop. <Score label="Hi"
value="bloom + CA + scanlines" /> <Score label="Lo" value="emissive only" />

The low tier has no post-processing at all. Emissive materials carry the neon
look on their own, which turns out to be most of the effect anyway.
